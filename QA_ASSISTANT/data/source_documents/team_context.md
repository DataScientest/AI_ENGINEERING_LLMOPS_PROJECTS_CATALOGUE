# Team context

## The team

The RoomBook team has seven people: six developers and one QA engineer. The product owner is shared with another team.

Since the developers started using AI assistants to write code, they deliver user stories about twice as fast. The QA engineer is the only person who writes test cases and maintains the automated suite. Review of new tests is done by the QA engineer and, when time allows, by one developer.

## How a story moves today

1. The product owner writes a story with acceptance criteria in the tracker.
2. A developer implements it and opens a pull request.
3. The QA engineer reads the story and the criteria, writes the test cases (nominal, limits, errors), then automates the ones worth keeping in the existing suite.
4. The pull request is merged when the suite is green and the QA engineer agrees.

Stories wait for step 3 more and more often. The QA engineer estimates between 45 and 90 minutes to design the cases of an average story, and the same again to automate them.

## Constraints

- No additional QA hire is planned.
- The existing suite (`data/application/tests/`) uses shared fixtures that must be reused rather than rewritten.
- Nothing generated by a tool is merged without a human review.
- Tickets are written by several people and are not always precise.
